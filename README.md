# Счётчик шагов (Android, Realme 10)

Свой алгоритм подсчёта шагов по акселерометру. Для проверки точности рядом показывается
встроенный аппаратный шагомер телефона. Разница между ними выводится в процентах.

## Как получить приложение

APK в этой среде собрать не удалось (нет Android SDK), поэтому два варианта:

**Вариант A. Android Studio (проще всего, если стоит на компьютере)**
1. File → Open → выбрать папку `StepCounter`. Дождаться синхронизации Gradle.
2. Подключить телефон по USB (включить «Отладку по USB»), нажать Run.
   Либо Build → Build APK(s) и перекинуть `app-debug.apk` на телефон.

**Вариант B. GitHub Actions (без установки чего-либо)**
1. Создать пустой репозиторий на GitHub и залить в него содержимое папки.
2. Вкладка Actions → Build APK → дождаться зелёной галочки → внизу скачать artifact `StepCounter-debug-apk`.
   (Сборка сначала гоняет тесты алгоритма и ядра штрафов, и только потом собирает APK.)
3. Распаковать, перекинуть `app-debug.apk` на телефон и установить (разрешить установку из неизвестных источников).

## Настройка на Realme 10 (важно)

Realme UI агрессивно убивает фоновые приложения. Иначе счёт остановится при выключенном экране:
1. В приложении нажать «Разрешить работу в фоне» и выбрать «Разрешить».
2. Настройки → Приложения → Счётчик шагов → Использование батареи → «Разрешить фоновую активность» и «Разрешить автозапуск».
3. Открыть список недавних приложений и «закрепить» (замочек) карточку приложения.

## Как проверить точность

1. Нажать «Запустить счёт», убрать телефон в карман.
2. Пройти ровно 100 шагов, считая вручную. Сверить три числа: ваши 100, «мой алгоритм» и «шагомер телефона».
3. Повторить с телефоном в руке, в сумке, в быстром темпе, на лестнице.

## Структура

- `StepDetector.java` — алгоритм (чистая Java, без Android). Параметры в начале файла.
- `StepService.java` — служба переднего плана: пакетный опрос акселерометра (50 Гц, задержка до 2 с), экономит батарею.
- `Store.java` — хранение по дням.
- `tools/SimTest.java` — проверка алгоритма на синтетических сигналах:
  ```
  javac -d out app/src/main/java/com/stepcounter/app/StepDetector.java tools/SimTest.java
  java -cp out SimTest
  ```

## Что делает алгоритм

Модуль вектора ускорения (не зависит от положения телефона) → вычитание гравитации → сглаживание →
поиск пиков с адаптивным порогом → шаги засчитываются, только когда обнаружен ритм
(5 подряд похожих по интервалу пиков). Ритмичность отсекает тряску и случайные движения.

## Ограничения

- Параметры проверены на синтетических сигналах, не на реальной ходьбе. После первых прогулок их
  стоит подстроить (если не хватает шагов — уменьшить `MIN_PROMINENCE` или `ENTER_PEAKS`;
  если много лишних — увеличить).
- Ходьба с коляской/тележкой, когда телефон почти не колеблется, может считаться хуже.
- Первые 5 шагов серии засчитываются с небольшой задержкой (когда подтверждается ритм).

## Обязательство: штраф за невыполненную цель

Как это работает:
1. «Цель и штраф» → указать шагов в день и сумму штрафа. Обязательство начинается завтра.
2. После конца дня (при первом срабатывании службы после полуночи) день оценивается. Если шагов меньше цели,
   в журнал пишется штраф и вызывается перевод в копилку. Если телефон был выключен, пропущенные дни
   догоняются при следующем запуске. День без данных считается невыполненным.
3. Ужесточить цель или штраф можно сразу. Ослабить только с задержкой 7 дней, иначе в плохой день
   достаточно было бы снизить цель.
4. Журнал (`ledger.log`) только добавляется, записи связаны хэшами. Правка или удаление записи
   в середине обнаруживается, расчёт при этом останавливается и приложение показывает предупреждение.
5. Источник «официальных» шагов по умолчанию: шагомер телефона (а если его нет, то мой алгоритм).
   Меняется в `StepSource` / `Engine.changeCommitment`.

**Деньги пока не двигаются.** За перевод отвечает `PaymentProvider`, сейчас подключена заглушка
`VirtualVault`, которая только подтверждает перевод. Чтобы штрафы стали настоящими, нужна реализация под
конкретный банк или платёжный сервис (единственное место для правки: `Engine.provider()`).
Требование к ней: один и тот же ключ операции не должен списывать деньги дважды.

**Главное ограничение.** Пока всё хранится на телефоне, "нельзя трогать" держится на честности:
чистка данных приложения, удаление приложения или root обходят защиту. По-настоящему неотзываемой
копилка становится только на стороне банка или сервера (счёт, с которого нет вывода, и копия
журнала на сервере).

Проверка ядра без телефона:
```
P=app/src/main/java/com/stepcounter/app
javac -encoding UTF-8 -d out $P/StepSource.java $P/Commitment.java $P/Ledger.java $P/PaymentProvider.java $P/VirtualVault.java $P/Settler.java $P/Fmt.java tools/com/stepcounter/app/CoreTest.java
java -cp out com.stepcounter.app.CoreTest
```
